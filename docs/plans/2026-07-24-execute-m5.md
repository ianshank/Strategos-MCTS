## Objective

Run the gate. That is the plan. M5's number is one command against a trained checkpoint:
`python -m src.benchmark.policy_lift --domain chess` over ≥100 games, gate met when the lift's
**95% Wilson-CI lower bound clears 20%** (`lift_ci_lower_pct >= 20`, `src/benchmark/policy_comparison.py:78-86`).
Either outcome is a deliverable: the artifact `benchmarks/results/m5_policy_lift.json` is committed
(AC-3 accepts exit 0 *and* exit 1), and `docs/STATUS.md` records the raw fields. Nothing else in M5 lands
first.

**Boundary.** This gate measures whether *learning improved decisions under identical search* — a trained
vs an untrained policy/value network, both arms under `NeuralMCTS`. It does **not** measure whether MCTS
beats a single-shot LLM on reasoning or code. That is a real question, deferred with named building blocks
in the final section — it is a different claim under a different spec.

## Ground rules

- **Nothing else lands until the number exists.** The only exceptions are this docs PR and the one-line
  `docs/STATUS.md` coverage-remnant fix that ships with it.
- **`policy_lift` is the sole authority** for the ≥20% claim (`specs/m5_policy_lift.SPEC.md:35`); gate
  semantics in `src/benchmark/` — thresholds, CI math, exit codes — are frozen (`:31`).
- **Reasoning/planning stay smoke-only** and never headline (`specs/m5_policy_lift.SPEC.md:36`;
  `docs/STATUS.md:103-105`).
- **Publish either outcome.** A not-met gate is a committed negative result, not a failure to deliver.

The operational runbook of record is `docs/STATUS.md` §"M5 chess gate — operator runbook (GPU)". **If this

## Statistical reality (pre-registered)

- **n=100 needs a true win-rate ≈ 0.70** for the Wilson lower bound to credibly clear +20%
  (`docs/STATUS.md:101-102` — "that is intentional"). A genuine 60%-win model will *correctly* fail the gate.
- **Draw dilution.** Draws count as half-wins (`src/benchmark/policy_comparison.py:209-210`), so a
  high-draw run compresses successes toward 0.5 and measured lift toward 0. The expected failure mode for an
  undertrained chess net is "near-zero lift with many draws" — that is *gate not met*, not a harness bug.
  Read the draw count out of the arena logs before blaming the harness.
- **Fail-closed.** No CI ⇒ `meets_target` is false (`:82-86`); the point estimate is reporting-only (`:88-91`).
- **Do not shrink `--num-games`** to save GPU time: below the recommended n the CI widens (warning at
  `:152-160`) and AC-3 requires ≥100 anyway.

## Validity preconditions and provenance

**Validity.** Already landed (2026-07-23/24): the arena win/loss tally is read from model1's own
perspective, the per-ply network swap clears the previously network-blind eval cache, and arena search runs
with root noise off (`docs/STATUS.md:155-162`). These make the measurement *valid*; they cannot pre-guarantee
AC-4. **Still open:** the negamax value-sign audit of `src/framework/mcts/neural_mcts.py` (`docs/STATUS.md:161-162`).
Decision rule: complete that audit — or at minimum run the bounded CPU smoke
`tests/integration/benchmark/test_chess_gate_smoke.py` — *before* burning GPU-hours. If it surfaces a sign
bug, that fix lands first; it lives in `src/framework/` (outside the frozen gate semantics) and needs its own
spec or `No-Spec` route.

**Provenance (no code change; gate semantics untouched).** The artifact's `run` block already records seed,
device, `num_simulations`, `max_moves`, checkpoint path, and network shape
(`src/benchmark/policy_lift.py:388-399`; see `benchmarks/results/reasoning_smoke_lift.json` for the shape).
It records no config hash and no checkpoint digest. When committing `m5_policy_lift.json`, record manually in
STATUS.md next to the raw-fields table: the **git SHA** of the producing tree, the **`sha256sum`** of the
checkpoint `.pt` and its `.meta.json`, and the exact command line. This extends the pin-the-number norm
without touching `src/benchmark/`.

## P1 — framing follows the number (decision tree, pre-committed)

Written before P0 executes so the result cannot renegotiate the framing.

- **Gate clears (`meets_target: true`, exit 0).** The chess lift + Wilson CI replaces "No ≥20% claim exists
  yet." at `docs/STATUS.md:106`; a human flips the spec to `verified` with `test_m5_lift_gate.py` active
  (AC-4); the `planning/milestones.yaml` M5 note is updated (its "Remaining: run the lift benchmark …"
  clause is then done).
- **Gate does not clear (exit 1).** Commit the artifact anyway — it is a valid AC-3 result. STATUS.md records
  the honest negative as raw fields; the spec stays `approved`. Next-step menu, ordered by the artifact's own
  diagnostics: inspect the **draw fraction first** — if draws dominate, the lift is diluted and more training
  precedes any other change; then more training iterations; then more simulations (train-time and/or
  eval-time); only then hyperparameters. **Not on the menu:** changing the target, n, confidence, or gate
  semantics to make the number pass (`specs/m5_policy_lift.SPEC.md:31`).
- **Exit 2 / crash.** An operational bug, not a gate outcome. Commit nothing; fix and rerun.

A not-met gate is a deliverable, not a failure: "trained-policy lift on chess at iteration N is X% [CI lower
Y%]" is publishable evidence either way. That was the best idea in the v1 draft and it survives here
unchanged.

## Deferred — does MCTS beat a single-shot LLM on reasoning/code?

This is the v1 draft's real interest, and it is out of M5's scope — a different question under a different
spec. Kept visible so it can be promoted to a phase later.

- **What exists.** `src/api/comparison_service.py` (`ComparisonService` — single-shot vs MCTS on one query,
  structured result with scores/latency/improvement; driven by `demo.py --provider mock|openai|anthropic`,
  `demo.py:507-509`) and `src/framework/mcts/llm_guided/benchmark/runner.py` (a HumanEval benchmark runner —
  library API with seed/timeout/sampling config, no CLI).
- **What building the benchmark would take.** (1) a dataset loop over `ComparisonService` or the HumanEval
  runner with a real provider; (2) real datasets — HumanEval via the existing runner, but GSM8K/MATH/MBPP
  would need data the repo does not have (today's fallback is a 2-item hardcoded mock,
  `training/benchmark_suite.py:1125-1171`); (3) an objective per-domain scorer (exact-match for GSM8K; the
  `training/` LLM judge is an unimplemented stub, `:391-394`); (4) cost/latency accounting (already in
  `ComparisonService`'s result shape); (5) **a new spec** — `policy_lift` is the sole authority for the *M5*
  claim, so an LLM-arm benchmark is a separate claim with its own pre-registered gate; (6) a budget estimate
  (N problems × 2 arms × per-node LLM calls).
- **Scope.** M5's gate asks whether learning improved decisions under search; this benchmark would ask
  whether search improves an LLM. Deferring it is scope hygiene, not avoidance.
